# Установка openmediad на Яндекс Станцию Мини 3

Пошагово: сборка → проба без установки → установка → настройки → если что-то не так → удаление. В конце — чек-лист
проверки вехи М1 на живой колонке.

> Эта версия ещё не проверялась на живой колонке. Сначала попробуйте `start` (до перезагрузки) и только потом `install`.
> Любой шаг откатывается: колонка с выключенным openmediad работает штатно.

## 1. Что нужно

- Яндекс Станция Мини 3 (`bergamot`) с доступом root по SSH: `ssh -p 2222 root@<адрес>` (пароль пустой).
- Компьютер с Go 1.27+ и `ssh` (Windows, Linux или macOS).
- На колонке ≈30 МБ свободного места на `/data`.

## 2. Сборка и заливка

```sh
go run ./tools/build -deploy 192.168.1.12      # собрать под колонку и залить в /tmp/openmediad/openmediad
```

По умолчанию собирается профиль `standard` (музыка Яндекса, голос Алисы, звонки, спектр для дисплея, отладочная страница). Другие:
`-profile core` (только ядро), `-profile full` (всё готовое, включая опытное), `-with bt-out`, `-without debug-page`; список компонентов с
паспортами — `go run ./tools/build -list` и [COMPONENTS.md](COMPONENTS.md).

Без `-deploy` бинарник окажется в `dist/openmediad`. Залить его вручную можно так (scp на колонке нет):

```sh
ssh -p 2222 root@192.168.1.12 'mkdir -p /tmp/openmediad && cat > /tmp/openmediad/openmediad && chmod +x /tmp/openmediad/openmediad' < dist/openmediad
```

`/tmp` на колонке — это ОЗУ: после перезагрузки файл исчезнет (установленная копия живёт на `/data`).

## 3. Проба без установки

```sh
ssh -p 2222 root@192.168.1.12
cd /tmp/openmediad
./openmediad doctor     # модель, прошивка, iptables, aplay, место, память — что не так и как исправить
./openmediad start      # включить до перезагрузки
./openmediad status     # что играет сам, 4 соединения платформы через шим, память
```

`start` запускает стража, а он — демон и правило iptables. Если платформа уже подключена к штатному плееру, тот
перезапускается: штатный лаунчер поднимает его за секунду, но плеер, стоявший на паузе, при этом теряется. Затем команда
ждёт, пока все 4 соединения платформы пойдут через openmediad. Если не вышло, всё откатывается.

Теперь попросите Алису включить музыку, поставить таймер, ответить на вопрос (чек-лист — §8). Журнал с пояснениями
простыми словами — `./openmediad logs -f -why` или страница **http://адрес-колонки:6701/** с компьютера в той же сети.

Выключить: `./openmediad stop` — музыка встанет на паузу с текущей позицией и продолжится у штатного плеера.

## 4. Установка

```sh
./openmediad install -dry-run   # что будет сделано
./openmediad install            # установить (спросит подтверждение)
```

Что делает `install`:

1. Проверки: модель (`bergamot`, иначе отказ без `-force`), прошивка (незнакомая — предупреждение), root, таблица `nat`
   у iptables, `/usr/bin/aplay`, место на `/data`.
2. `/data/opt/openmediad/`: бинарник `bin/openmediad`, страж `guard.sh`, настройки `openmediad.conf` (если их ещё нет).
3. Бэкап: `backup/manifest.json` — что меняется в rootfs, был ли файл раньше, sha256.
4. rootfs (на время одной правки — `mount -o remount,rw /`, сразу после — `sync` и `remount,ro`):
   - `/etc/init.d/S98openmediad` — автозапуск (запускается раньше `S99quasar`, поэтому при загрузке перезапускать плеер
     не нужно);
   - ссылка `/usr/bin/openmediad` — чтобы команда работала из любого каталога (если такой файл уже есть, он не трогается).
5. Запуск (как `start`) и проверка, что платформа подключилась через openmediad.

Ошибка на любом шаге — всё сделанное откатывается. Повторный `install` более новой версии — это обновление:
настройки сохраняются, при неудаче возвращается прежняя версия.

| Где | Что |
|---|---|
| `/data/opt/openmediad/bin/openmediad` | бинарник |
| `/data/opt/openmediad/guard.sh` | страж (пишется из бинарника; не правьте) |
| `/data/opt/openmediad/openmediad.conf` | настройки |
| `/data/opt/openmediad/backup/` | бэкап изменённого в rootfs и `manifest.json` |
| `/data/opt/openmediad/state/` | отметка «автозапуск выключен» |
| `/etc/init.d/S98openmediad` | автозапуск |
| `/usr/bin/openmediad` | ссылка на бинарник |
| `/tmp/openmediad/` | сокет команд, pid, журнал стража `guard.log`, ошибки демона `daemon.err` (ОЗУ) |

## 5. Настройки

```sh
openmediad config                              # открыть в редакторе ($EDITOR, nano или vi) с проверкой
openmediad config set debug-page.enabled false # один ключ
openmediad config get general.log_level
openmediad config check                        # только проверить
openmediad config reset                        # вернуть файл по умолчанию (старый — в .bak)
```

Каждый ключ в файле прокомментирован. Секция компонента называется так же, как компонент (`[yandex-music]`, `[bt-out]` …); все компоненты и их паспорта — в [COMPONENTS.md](COMPONENTS.md). Главное:

- `[yandex-music]`, `[alice-voice]`, `[system-sounds]` → `enabled = false` — эту часть снова играет штатный плеер;
- `[debug-page] listen` — отладочная страница (по умолчанию открыта компьютерам домашней сети, только чтение);
  `enabled = false` — выключить;
- `[general] log_level` — `trace` пишет каждый кадр шины (для разбора проблем), `info` — обычный;
- `[focus] duck_gain` — громкость музыки, пока Алиса слушает или говорит;
- `[fallback] max_crashes` — после стольких быстрых падений подряд страж сдаётся до перезагрузки.

Уровень журнала, маршруты и приглушение применяются сразу. Остальное — после `openmediad restart` (команда `config`
скажет, что именно).

## 6. Если что-то не так

1. `openmediad doctor` — проверки с подсказками.
2. `openmediad status` — работает ли страж и демон, стоит ли правило, сколько соединений через шим.
3. `openmediad logs -why` — журнал демона; `/tmp/openmediad/guard.log` — журнал стража;
   `/tmp/openmediad/daemon.err` — ошибки демона при падении.
4. `openmediad stop` — колонка снова полностью штатная до перезагрузки.

**Алиса замолчала, и команда openmediad не помогает** (так быть не должно; на этот случай):

```sh
iptables -t nat -D OUTPUT -p tcp -d 127.0.0.1 --dport 9906 ! -s 127.0.0.2 -j REDIRECT --to-ports 19906
```

Это снимает правило: платформа переподключится к штатному плееру сама. Чтобы openmediad не запустился после
перезагрузки, достаточно убрать стража, rootfs при этом не трогается (скрипт автозапуска без стража ничего не делает):

```sh
mv /data/opt/openmediad/guard.sh /data/opt/openmediad/guard.sh.off && reboot
```

**Страж сдался** (в `status`: «сдался после 3 падений подряд»): колонка работает штатно. Причина — в
`/tmp/openmediad/daemon.err` и `guard.log`. Попробовать снова — `openmediad start`.

**Обновление прошивки** может стереть скрипт автозапуска: колонка просто станет штатной. `status` и `doctor` это
заметят, `openmediad install` (бинарник на `/data` остаётся) вернёт автозапуск. На незнакомой прошивке протокол мог
измениться — следите за `openmediad logs`.

## 7. Удаление

```sh
openmediad uninstall -dry-run   # что будет сделано
openmediad uninstall            # удалить, настройки оставить
openmediad uninstall -purge     # удалить и настройки
```

Движок останавливается (музыка переходит к штатному плееру), файлы rootfs возвращаются по манифесту со сверкой sha256,
`/data/opt/openmediad` удаляется, команда ждёт, пока платформа подключится к штатному плееру напрямую. Файлы,
изменённые кем-то после установки, не трогаются — о них будет предупреждение.

Выключить автозапуск, не удаляя: `openmediad disable` (включить — `enable`).

## 8. Чек-лист проверки вехи М1 на колонке

Громкость во время проверок держите низкой: платформа сама поднимает громкость звонков, поэтому громкость удобно
зажать сценарием `scripts/dev/volume-clamp.sh`. **Не просите Алису «удали все будильники»**: удалятся и настоящие.

Демон и паритет (фаза 3), после `openmediad start`:

- [ ] `status`: 4 соединения через шим, «играет сам: музыку Яндекса, голос Алисы, звонки»;
- [ ] Алиса отвечает голосом (в `logs`: голос играет openmediad);
- [ ] музыка: «включи музыку», «пауза», «продолжи», «следующий», «перемотай на минуту вперёд»;
- [ ] пока Алиса слушает или говорит, музыка тише, потом громкость возвращается;
- [ ] таймер на 10 секунд звонит; «стоп» его выключает;
- [ ] звук после «Алиса» и щелчок громкости звучат один раз (в `logs`: «системный звук: запуск …», затем «доиграл»);
- [ ] спектр на дисплее во время музыки и ответа;
- [ ] страница http://адрес:6701/ показывает живой журнал;
- [ ] `openmediad stop` во время музыки → музыка продолжается у штатного плеера с того же места.

Страж и резерв (фаза 4):

- [ ] `start` и `stop` работают без ручных команд;
- [ ] `kill -9 $(cat /tmp/openmediad/daemon.pid)` → правило снято за ≤2 с (`iptables -t nat -S OUTPUT`), Алиса
      отвечает; страж перезапускает демон, платформа возвращается через шим;
- [ ] три быстрых падения подряд → страж сдаётся, колонка штатная (`status` об этом говорит).

Установка (фаза 5):

- [ ] `install` → `reboot` → после загрузки `status`: 4 соединения через шим, всё из фазы 3 работает;
- [ ] `install` поверх (обновление) сохраняет настройки;
- [ ] `uninstall` → `/etc/init.d/S98openmediad` и `/usr/bin/openmediad` нет, `status`: платформа напрямую;
- [ ] длинный прогон ≥2 ч (музыка с паузами, ответы Алисы, таймер) без сбоев; память демона в `status` — в пределах
      PLAN.md, §13.1.

Результаты с датой и версией прошивки — в `docs/research/HISTORY.md`.

## 9. Bluetooth-наушники (опытное)

Колонка может играть в Bluetooth-наушники: например, голос Алисы — на динамиках, музыка — в наушниках. Компонент `bt-out` опытный: с наушниками
проверен (музыка и ответы Алисы поверх неё), но чек-лист ниже пройден не весь, поэтому в сборку по умолчанию пока не входит (профиль `standard`; добавляется `-with bt-out` или профилем `full`). Команда `openmediad bt` появляется вместе с `bt-out` и `bt-in`. Пока наушники
подключены, демон держит в них канал (в паузах — тишина) и сообщает платформе, что канал простаивает: иначе она принимает звук в наушниках
за звук телефона и останавливает музыку (BUS-PROTOCOL.md, §2.7б).

```sh
go run ./tools/build -with bt-out -deploy 192.168.1.12     # на компьютере: сборка с компонентом
```

На колонке (громкость перед проверкой держите низкой):

```sh
/tmp/openmediad/openmediad restart                  # запустить новую сборку
openmediad bt list                                  # адаптер, известные устройства, громкость колонки
openmediad bt scan                                  # наушники — в режиме спаривания; ищет 12 с
openmediad bt pair AA:BB:CC:DD:EE:FF                # спарить, доверять, подключить
openmediad test-sound bt-out                     # тихий тон в наушники мимо движка
openmediad bt use AA:BB:CC:DD:EE:FF                 # выводить в эти наушники (any — в любые)
openmediad config set route.music '["bt-out", "speaker"]'   # музыка — в наушники, без них — на динамики
openmediad restart                                  # настройки компонента применяются при перезапуске
```

Пока наушники подключены, кнопки, голос и экран колонки управляют их громкостью, а громкость динамиков (голос Алисы) остаётся прежней
(`bt-out.hold_speaker = true`); отключились — уровень на экране возвращается к динамикам (голосом платформа ставит только чётные
уровни, нечётный вернётся на шаг тише). «Алиса, выключи блютуз» отключает наушники, и колонка не подключает их сама до «включи блютуз».
Пока подключён телефон, наушники колонка сама не подключает (иначе телефон отключится). Анимация частот всё время, пока играет музыка (штатно платформа гасит её
через 15 с и после ответа Алисы): `openmediad config set spectrum.always true`.

Голос Алисы и звонки можно направить так же (`route.voice`, `route.alert`). Громкость наушников повторяет громкость колонки (кнопки, «громче»);
`bt-out.volume = "headphones"` — громкостью управляют сами наушники. Пока выбранные наушники не подключены, колонка раз в 30 с
пробует подключить их сама (`bt-out.reconnect`): когда Bluetooth колонки «выключен», наушники не могут подключиться к ней первыми.

Вернуть как было: `openmediad config set route.music '["speaker"]'`, `openmediad bt forget АДРЕС`, `openmediad restart`.

**Звук с телефона через openmediad (опытное, компонент `bt-in`).** Телефон по-прежнему подключается к колонке штатно («Алиса, включи блютуз»),
управление (пауза, «дальше», громкость) остаётся у Алисы, но сам звук идёт через движок: приглушается на время ответа по `[focus] duck_gain`,
рисует спектр и выводится по маршруту `[route] music`. Пока компонент работает, штатный `bluealsa-aplay` остановлен; `openmediad stop` его
возвращает.

```sh
go run ./tools/build -with bt-out,bt-in -deploy 192.168.1.12   # на компьютере
```

На колонке: `openmediad restart`, подключить телефон и включить на нём музыку; `openmediad status` — строка «телефон: … играет через
openmediad». Выключить: `openmediad config set bt-in.enabled false`, `openmediad restart`.
