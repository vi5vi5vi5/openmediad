# scripts/dev/soloist-o3 — Soloist со звуком на колонке (опыты О1 и О3)

Набор проверяет главное из `docs/MUSIC-PLAN.md`: **берёт ли Soloist ваш аккаунт** (Нигерия, Россия, новый, Premium), **играет ли он через нашу замену `libpulse` на колонке** и как живёт по памяти и кэшу. Ничего не меняет в штатных настройках колонки: всё лежит в `/data/soloist-o3` (флеш) и `/tmp` (ОЗУ), `clean` стирает всё. Музыка идёт мимо движка openmediad (сырым `aplay` на общий смеситель `default`): приглушения под Алису здесь нет, это следующий этап.

## Что проверено, а что нет (31.10.2026, пока вы были не дома)

| Проверено на колонке | Не проверено (нужен ваш ключ и вы у колонки) |
|---|---|
| Soloist 1.3.10.31 стартует с glibc 2.41, ждёт логина, mDNS виден, WebSocket отвечает; 9 минут игры: память стабильна (PSS 37…44 МБ), звуковой кэш растёт в каталог `-C` (≈ +25 МБ за 9 минут при частых переключениях) | вытеснение кэша при лимите 100 МБ (свободно на `/data` остаётся ≈ 93 МБ и убывает) |
| Шим `libpulse.so.0`: 48 из 48 символов Soloist, `shim_test` играет тон; **со Spotify вживую (вечер 31.10.2026): музыка играет, ползунок громкости с телефона работает, `underflow` 0** | задержка паузы/перемотки/следующего трека, поведение при голосовом запросе к Алисе во время музыки |
| Вход нового аккаунта (Нигерия, Premium, из России): `UCS login result: outcome=success` | `--single-track`, время холодного старта |
| `deploy`, `setkey`, `serve`, `watchdog`, `status`, `watch`, `trace`, `ctl`, `tone`, `stop`, `clean` | |

**Обязательное условие: `abi.cp15_barrier=2` на колонке.** Без него Soloist зависает на первом входе (причина ниже, «Что известно заранее»). Команда `ssh alice 'echo 2 > /proc/sys/abi/cp15_barrier'` действует до перезагрузки; после перезагрузки колонки её нужно выполнить снова. Скрипты набора эту настройку **не меняют** (системный параметр, решение за вами).

## Что нужно от вас

1. Ключ Soloist: Developer Dashboard → `https://developer.spotify.com/dashboard/soloist` (аккаунт с Premium; ключ личный, не делитесь, не коммитьте). Сохраните его в файл **вне репозитория**, например `key.txt`.
2. Приложение Spotify (телефон или ПК) в **той же Wi-Fi сети**, что и колонка; VPN на телефоне на время опыта лучше выключить (мешает mDNS).
3. Git Bash на ПК (`ssh`, `curl`, `python`); колонка по `192.168.1.12:2222` (как в остальных `scripts/dev`).

## Шаги (Git Bash, из корня репозитория)

```bash
O=scripts/dev/soloist-o3/o3.sh
sh $O deploy                 # Soloist, glibc 2.41, шим -> колонка /data/soloist-o3 (всё нужное уже скачано и собрано в captures/soloist-o3)
sh $O tone                   # ПРОВЕРКА ШИМА БЕЗ SPOTIFY: на колонке ~5 секунд тон «ля» (440 Гц), пауза, 660 Гц; в конце «ИТОГ ХОРОШО»
sh $O setkey < key.txt       # ключ на колонку, права 0600
sh $O serve                  # запуск; выводит статус
sh $O trace 180              # в ДРУГОМ окне: поток событий WebSocket 3 минуты (вход, playback_state, ошибки)
```

Если `tone` молчит: `OMD_SHIM_DEBUG=1 sh $O tone`, смотрите строки `[shim …]`; громкость колонки (Master) не меняется скриптами.

В приложении Spotify откройте список устройств и выберите **`omd-o3`**, включите трек: он должен зазвучать на колонке (в идеале 10 разных, в том числе русских). Дальше:

```bash
sh $O status                 # процесс, память, диск, кэш, ключевые строки журнала
sh $O log 80                 # последние строки журнала Soloist (там же строки шима и aplay)
sh $O ctl now                # что играет (после входа)
sh $O ctl queue              # очередь и источник (context / queue / autoplay)
sh $O watch 120 5            # CSV раз в 5 с: MemAvailable, PSS, потоки, размер каталогов
sh $O stop                   # остановить
sh $O clean                  # остановить и стереть /data/soloist-o3 (ключ, сеанс, кэш)
```

Режим `sh $O pair` ждёт сопряжения до 3 минут и завершается: сеанс сохраняется (нужен для будущего `--single-track`).

Настройки (переменные окружения пробрасываются на колонку): `VOL=30 sh $O serve` (начальная громкость Soloist, по умолчанию 50), `NAME=...` (имя устройства), `OMD_SHIM_VOLUME=linear|cubic|off` (как громкость Soloist превращается в усиление: `linear` по умолчанию, `cubic` как в PulseAudio, `off` — игнорировать и регулировать только Master), `OMD_SHIM_DEBUG=1` (журнал каждого вызова), `OMD_PCM_DEV`, `OMD_PCM_APLAY_ARGS`, `OMD_PCM_FIFO` (писать S16LE в FIFO вместо `aplay`), `OMD_SHIM_LAT_US`, `OMD_SHIM_NO_UNDERFLOW=1`. Полный список — в шапке `shim/libpulse_shim.c`.

## Как читать результат

| Что видно | Что значит |
|---|---|
| `trace`: `auth_state` с `logged_in:true`, в журнале «Session ... created» без ошибок | вход с вашим аккаунтом работает |
| В журнале `Access denied from backend`, `session_access_denied`, `session_auth_code_grant_failure` | сессию Spotify не выдал (аккаунт/регион/ключ): сравните с официальным приложением на этом же аккаунте и запишите текст (так выглядит spotify/soloist#13) |
| `playback_state` со `status:"playing"` и растущим `position_ms` в `position_sync` | аккаунт получает аудио: **главный признак, что новый аккаунт не упирается в отказ ключа** |
| В журнале `[shim …] pa_stream_new(...)`, `вывод: aplay pid=…` и слышен звук | шим работает со Spotify вживую |
| `[shim …] поток отклонён: формат …` | Soloist запросил формат, которого шим не поддерживает (поддержаны float32le и s16le, 1–2 канала): пришлите строку |
| `[shim …] underflow` в середине трека | шим не успевает с данными или Soloist отдаёт их рывками; рядом `aplay: underrun` |
| Звук есть, но «дальше»/пауза реагируют с задержкой около 0,3 с | ожидаемо: буфер `aplay` 150 мс + канал 16 КБ; flush обрывает `aplay` сразу |
| Звука нет, в журнале `error` / вечный `buffering` / `idle` | различайте по тексту `error` и журналу (шим, вход или отказ воспроизведения), а не гадайте |
| Устройства `omd-o3` нет в приложении | mDNS не дошёл: сеть/VPN; проверьте `status` (`udp 5353 держателей` должно быть 2), перезапустите `serve` |

Запишите: версия (`soloist -V`), время от выбора устройства до `logged_in:true`, тексты ошибок, `MemAvailable` и PSS во время игры, рост `data/cache` и каталога `-C` за 10 треков (`watch`), как ведут себя пауза, перемотка, следующий трек, autoplay после одиночного трека (в приложении Spotify отдельно выключите Autoplay и сравните), громкость слайдера.

## Что известно заранее (проверено 31.10.2026, подробности в `docs/MUSIC-PLAN.md` §10)

- **Зависание без `cp15_barrier=2`.** После первого запроса Spotify (zeroconf `getInfo`) главный поток Soloist уходит в бесконечный цикл: 100% ядра, ни одного системного вызова, mDNS и вход не отвечают, колонка пропадает из списка. Причина (по выборке адреса через `ptrace`): цикл `ldrexb … mcr p15,0,r0,c7,c10,5 … strexb` в самом бинарнике; при `cp15_barrier=1` ядро эмулирует CP15-барьер через ловушку, выход из ловушки сбрасывает монитор эксклюзивного доступа, и `strexb` не удаётся никогда. Лечение: `cp15_barrier=2` (аппаратное исполнение). Команда `watchdog` вместо `serve` запускает Soloist со сторожем, который перезапускает его при 100% CPU трижды подряд; с `cp15_barrier=2` сторож не нужен, но не мешает.
- Soloist 1.3.10.31 требует GLIBC до 2.38; колонка имеет 2.30, поэтому рядом лежит glibc 2.41 и запуск идёт через `ld-linux-armhf.so.3 --library-path`. Системный glibc не меняется. Аудио-бэкенд (`libpulse.so.0`) Soloist подгружает только при воспроизведении: при старте его не видно.
- Простой: PSS ≈ 22 МБ, `MemAvailable` падает примерно на 3 МБ; mDNS занимает UDP 5353 рядом с `maind` и работает без правки `cp15_barrier`.
- Без `-C` Soloist не стартует (пытается создать `/root/.cache`); со `-C` каталог создаётся, но индекс кэша лежит в `<data-dir>/cache`: куда пойдёт звуковой кэш при игре — смотрите `status` и `watch`. `--cache-size` минимум 100 МБ, лимит нестрогий (spotify/soloist#8); на `/data` свободно ≈ 130 МБ.
- Crashpad не стартует при запуске через явный загрузчик (в журнале «install crash handler: NO») — безвредно.
- Сборка Soloist истекает через 90 дней (код выхода 10; на 31.10.2026 осталось 88); ключ виден в `/proc/<pid>/cmdline` (особенность Soloist); WebSocket слушает только `127.0.0.1:9090`.
- Условия Spotify (Developer Policy III.3, III.5, III.7 и др.) на такой запуск не заявлены как разрешающие; это личный опыт на своей колонке, `captures/` в `.gitignore`, сборку Soloist не распространять.

## Шим (shim/)

`shim/libpulse_shim.c` — замена `libpulse.so.0` для Soloist: потоковый mainloop, контекст, поток воспроизведения, громкость (`set_sink_input_volume`, `get_sink_input_info`), `cork`, `flush`, тайминги. Звук пересчитывается в S16LE и уходит в `aplay` (на каждое подключение потока; при flush `aplay` перезапускается за ≈ 20 мс) либо в FIFO. Ограничения опыта: формат только float32le/s16le, 1–2 канала; частоту не меняет (это делает `aplay` через `plug` на `default`); буфер 500 мс; объекты контекста и потока не освобождаются (утечка в десятки байт на трек); одна громкость на все потоки. Собран `zig cc` под `arm-linux-gnueabihf.2.30` по настоящим заголовкам PulseAudio 17 (компилятор сам сверил сигнатуры); перестройка: `ZIG=/путь/к/zig sh $O build-shim` (zig 0.17.0 лежит в временной папке сессии; официальная загрузка с `ziglang.org`, sha256 в шапке `shim/build.sh`).

## Дальше
