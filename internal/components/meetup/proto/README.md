# meetup/proto — клиент протокола MeetUp

Ровно та часть протокола [MeetUp](https://github.com/vi5vi5vi5/MeetUp), которая нужна колонке. Спецификация — `Server/docs/desktop-client-guide.md`
в репозитории MeetUp; номера разделов в комментариях кода — оттуда.

| Файл | Что делает |
|---|---|
| `link.go` | `ParseLink`: ссылка `https://сервер/conference.html?room=КОД[#k=КЛЮЧ]` → сервер, комната, адрес WebSocket. Домены с национальными буквами переводятся в Punycode (`мит-ап.рф` → `xn----8sbwpsp.xn--p1ai`). `Link.Display` — вид для журнала без кода комнаты |
| `session.go` | `Join`: соединение и вход (`join` → `join_ok`); `Session.Run`: чтение чата и списка участников, проверка связи раз в 10 с; `SendChat`, `SetMic`, `SendAudio` (кадр двоичного протокола v2: Opus 48 кГц моно 20 мс в голосовой полосе) |
| `account.go` | `Login` и `Logout`: логин и пароль → кука сессии `meetup_session` (HTTP API). С кукой в рукопожатии сервер привязывает соединение к аккаунту (`Options.Session`, `Session.Account`); `UserIDOf` — аккаунт участника по его идентификатору в комнате |
| `cipher.go` | сквозное шифрование: ключ из ссылки (`KeyFromLink`) или из фразы (`KeyFromPhrase`, PBKDF2-SHA256), `Cipher` — AES-256-GCM для звука и чата. `cipher_test.go` сверяет с эталоном веб-клиента байт в байт |
| `prototest/` | поддельный сервер MeetUp для тестов: комната, аккаунты, пароль комнаты |

Двоичные кадры сервера (звук и видео остальных участников) читаются и выбрасываются без выделения памяти (`wsclient.Options.SkipBinary`).
История чата из `join_ok` не разбирается: команды, сказанные до входа колонки, она не выполняет.

Пароль комнаты — `Options.Password`. Сообщение чата под нашим ключом приходит в `Chat.Text` уже расшифрованным; `Chat.Encrypted` значит,
что прочесть его нечем (ключа нет или он чужой).

**Заглушки** (перечень с причинами — в [README компонента](../README.md#заглушки)): приём звука и видео, картинки чата, продление сессии аккаунта.

**Использует:** `libs/wsclient`.
