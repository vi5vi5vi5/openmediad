# core/daemon — демон

`openmediad run`. Единственное место, где всё соединяется: настройки → журнал → движок → шим и автомат `mediad` → сокет команд →
компоненты. Остальные пакеты знают друг о друге только через интерфейсы.

| Файл | Что делает |
|---|---|
| `app.go` | `Run`: порядок запуска и остановки; адреса шима (`19906` → `9906`, исходящие с `127.0.0.2`); сигналы: SIGTERM — мягкая передача плееров штатному `mediad`, SIGHUP — перечитать настройки |
| `components.go` | создаёт включённые компоненты и подключает их **по интерфейсам** (`mediad.Backend/VoiceBackend/FileBackend`, выход звука, «модуль» с `Start/Stop`, `StatusLine`, `OnDirective`, `InterceptPhrase`, `OnReply`, `OnButton`, `LogsDialog`, `Reload`); ошибка компонента демон не роняет |
| `control.go` | ответы на команды терминала: `status`, `logs`, `follow`, `reload`; что настройки применяются на ходу, а что после перезапуска |
| `router.go` | выбор выхода под класс звука по `[route]`: первый доступный из списка; выходы компонентов подключаются по имени |
| `intercept.go` | что делать с каждым кадром платформы: отдать автомату (штатному `mediad` не пересылать) или пропустить; запись кадров в журнал |
| `aliced.go` | слежение за диалогом Алисы: реплики — в журнал (если компонент просит), имена директив и окончательные фразы (`InterceptPhrase`) — компонентам |
| `buttons.go` | кнопка Алисы и жесты по колонке (видны только в `maind.log`, [core/quasar/buttons](../quasar/buttons/README.md)) — компонентам с `OnButton`; лог читается, только если такой компонент есть |
| `gate.go` | шлюз голоса: гасит ответ облака на фразу, которую выполнил компонент (голос не звучит, автомат получает те же события «запущен, закончен») |

**Зависит от:** почти всего из `core`. **Кто использует:** `cli/run.go`. Новых имён компонентов здесь быть не должно.
