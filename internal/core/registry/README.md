# core/registry — механизм компонентов

Что компонент такое для ядра. Сам список компонентов (паспорта) здесь **не** хранится: он лежит в
[`components/catalog`](../../components/catalog/README.md) и передаётся ядру при запуске (`registry.SetCatalog`), поэтому в ядре нет
ни одного имени компонента.

| Файл | Что делает |
|---|---|
| `info.go` | паспорт `Info` (имя, название, вид, **класс**, по умолчанию, опытный, **что требует** от прошивки и от компонентов, **что будет, если убрать**), `Tag()` — тег сборки `omd_<имя>`, `InBuild`; каталог: `SetCatalog`, `Lookup`, `BySection` |
| `registry.go` | `Component{Name, Defaults, Template, New}`; `Register` (из `init()` компонента), `Get`, `Compiled`, `Missing`, `All`, `Verify` (сверка с каталогом) |
| `env.go` | `Env` — службы демона для компонента (`Use[T](env, "engine")`: движок, автомат `mediad`, журнал, состояние) |
