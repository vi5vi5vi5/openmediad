# core/control/controltest — заготовки для тестов плееров

Нужно тому, кто пишет плеер для движка (как это делать — [docs/PLAYERS.md](../../../../docs/PLAYERS.md)) или источник команд (кнопки, наушники …).

* `Player` — поддельный плеер: состояние задаёт тест (`Set`, готовые `Playing()` и `Paused()`), команды записываются (`Done()`), можно сделать плеер
  глухим к источникам (`Refuse`), заставить Do сбоить (`Fail`) и подписаться на команды (`OnDo`).
* `Platform` — поддельная музыка Яндекса и автомат `mediad`: `SetPlaying`, сколько раз готовили очередь Яндекса (`Armed`) и забирали место (`TakeOvers`).
* `CheckPlayer(t, плеер)` / `Violations(плеер)` — **договор плеера**: `Accepts` одинаково отвечает на любой источник и не паникует; `State` быстрый, безопасен
  при параллельных вызовах и не противоречит себе; `Do` отвергает `Toggle` и незнакомые команды ошибкой и не зависает. Плеер подключают к подделкам
  (поддельный Soloist, а не настоящий), потому что проверка вызывает `Do` по-настоящему.

Тесты ядра (`core/control`) свои подделки держат внутри пакета: этот пакет импортирует `control`, и обратный импорт замкнул бы круг.

Тесты: `go test ./internal/core/control/controltest/`.
